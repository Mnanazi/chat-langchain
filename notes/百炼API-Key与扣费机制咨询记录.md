> 整理自一次围绕「本项目 `.env` 中的百炼 API Key、免费额度、账户扣费」的连续咨询。
> 目的：厘清阿里云百炼（DashScope OpenAI 兼容接口）的 Key / Base URL / 计费三者的关系，
> 并沉淀出「学习阶段如何不花账户余额」的可执行结论。
>
> 安全说明：本文档中所有 API Key 均以**掩码**形式展示，不记录明文；真实 Key 只应存在于本地 `.env`。

## 一、背景

- 本项目通过 `langchain-openai` provider，以 **OpenAI 兼容协议**调用阿里云百炼（DashScope），
  相关配置集中在 `.env`，并由 [`src/agent/llm.py`](file:///home/zhangsan/github-learning/chat-langchain/src/agent/llm.py) 的 `get_chat_model()` 统一构造模型。
- 使用过程中收到百炼欠费短信：早期充值的 5 元已耗尽并欠费 0.45 元，随后再次充值结清并恢复服务。
- 由此引出疑问：`.env` 里的 Key 到底是什么类型？为什么会扣钱？怎样切到"有免费额度"的模型以避免继续消耗账户余额？

## 二、三个核心概念（先建立正确认知）

### 1. API Key 是"账户级通行证"，不绑定任何单个模型

百炼官方规则：**同一个 API Key 可调用该账户有权限的所有模型**。在模型广场"为某个模型创建 Key"，
只是控制台帮你跳转到 Key 管理页并自动填了一个**描述标签**，建出来的仍是**通用 Key**，能调任意模型。

> 结论：**不存在"某个模型的专属 Key"这种东西**。Key 的"描述"（如"使用 qwen3.6-flash"）纯粹是给人看的记账名，平台不据此做权限限制。

### 2. `OPENAI_BASE_URL` 只是"请求发到哪里"的地址

- 它是一段**端点 URL**，不含任何凭证、不代表计费方式。
- 作用：让客户端把 `/chat/completions` 等请求发到**百炼北京地域的 OpenAI 兼容端点**，而非 OpenAI 官方。
- 它与 API Key 是**完全正交**的两件事：`BASE_URL` = 地址，`API_KEY` = 凭证。换 Key 不改地址，换地址也不改变 Key 的性质。

### 3. 一次调用"能否成功 + 花不花钱"的判定链

真正产生一次会扣费的调用，必须**三件事同时成立**：

1. 代码**实际发起**了请求（有人跑到那行调用）；
2. 请求头带上了**有效的 API Key**；
3. 请求里**指定了某个模型**。

由此推论：

- 只有 `BASE_URL`、没有效 Key → 返回 401，**不产生费用**；
- 有 Key 但没人调用 → **也不会有任何费用**；
- 扣不扣钱**不取决于 Key，而取决于"目标模型自己的额度状态"**。

**百炼扣费优先级**：`免费额度 > 资源包 > 节省计划 > 按量付费`。
即：调用一个"有免费额度"的模型时，**先扣它的免费额度**，耗尽后才走账户余额（按量付费）。
**唯一例外**：Token Plan / Coding Plan 的**专属 Key** 不消耗免费额度，会直接按量付费——但那是另一类 Key，与本项目无关。

## 四、免费额度机制与"自动切换"的可行性

### 平台侧的两个硬限制（务必知晓）

1. **没有对外查询"某模型剩余免费额度"的 API**。查看剩余额度只有三种途径——控制台「免费额度」页、「模型广场」详情页、「模型用量」页，全是网页，且**分钟级更新、需手动刷新**。
2. **额度用完没有提醒机制**；**系统也不会自动切换到其他有额度模型**，需手动改 `model` 参数。

因此，"精确判断剩余 < 1 万 token 再提醒"——**平台原生做不到**，任何本地实现都只能是估算。

### 免费额度规则要点

- 每个模型各有**独立**的免费额度（通常 1M token），**不跨模型合并/共享**。
- 带日期后缀的快照版本与不带日期的最新版本视为**两个独立模型**，各自独立额度。
- 额度有效期约 90 天，**到期或耗尽后自动失效**，继续调用即计费。
- 仅**华北2（北京）**地域模型享有免费额度。
- 主账号与其 RAM 子账号**共享**同一模型的额度。

### 落地方案（按推荐度）

- **前提（最重要，不改代码即可防扣费）**：
  1. 给要用的模型开启控制台里的「**免费额度用完即停**」——额度耗尽时调用直接报错而非扣费；
  2. 确认使用**通用 Key**（非 Token Plan 专属 Key），否则免费额度不生效。

- **方案 A（推荐）：报错驱动的自动切换模型池**。
  额度耗尽（配合"用完即停"）时调用会返回特定错误；捕获该错误即把 `OPENAI_MODEL` 切到下一个有额度模型重试。
  天然贴合本项目：所有调用走 `get_chat_model()`，且 [`src/agent/config.py`](file:///home/zhangsan/github-learning/chat-langchain/src/agent/config.py) 已有 `FALLBACK_MODELS` + `with_fallbacks` 降级结构可扩展。

- **方案 B（可叠加）：客户端 token 累计提醒**。
  在中间件里读取每次响应的 `usage_metadata`（input/output/total tokens）按模型累加到本地文件，接近上限时告警。
  局限：只统计本项目可见的消耗，属**估算**；可手动填入控制台"已用量"作为基准提升准确度。

- **方案 C（不推荐）：反查控制台内部接口**。需登录 Cookie、未公开、随时变更、脆弱且有合规风险。

## 五、风险提示与安全建议

1. **Key 不分模型 = 一把 Key 泄露即可被刷任意模型**，直接消耗账户余额。
2. 本次咨询中真实 Key 已在对话/截图中明文出现，建议到控制台对该 Key 点「**重置**」换一把，仅存于本地 `.env`，不要再贴入任何对话、截图或提交到仓库。
3. `.env` 属敏感文件，应确保已被 `.gitignore` 忽略，切勿提交。
4. 想彻底防意外扣费：给常用模型开「用完即停」+ 设置**高额消费预警**（日账单超阈值短信提醒）。

## 六、学习阶段的手动切换工作流（只改 `.env`，不改源码）

承接第四节：既然平台不提供额度查询 API、也不会自动切换，那么对学习项目而言，最省事且完全可控的做法就是——**人工定期看用量，额度将尽时手动改 `.env` 里的一行模型名**。下面记录这套想法与其可行性、步骤。

### 想法

学习过程中定期到百炼控制台查看**当前项目实际所用模型**的免费额度剩余；一旦发现剩余额度偏低，就手动把 `.env` 中项目调用的模型换成下一个仍有额度的模型。目标是：**每次只改 `.env` 一处，绝不改动项目源码。**

### 为什么可行（已核对源码）

本项目的模型选择是**纯环境变量驱动**、且收敛在唯一一处：

- [`src/agent/llm.py`](file:///home/zhangsan/github-learning/chat-langchain/src/agent/llm.py) 读取 `OPENAI_MODEL` 得到 `DEFAULT_CHAT_MODEL`，并拼出 `CHAT_MODEL_ID = openai:{OPENAI_MODEL}`；
- [`src/agent/config.py`](file:///home/zhangsan/github-learning/chat-langchain/src/agent/config.py) 的 `MODELS` 注册表、`DEFAULT_MODEL`、`GUARDRAILS_MODEL`、`FALLBACK_MODELS` 全部由该值动态生成。

因此 `OPENAI_MODEL` 填什么，**主 Agent、Guardrails 拦截、上下文摘要三处调用就统一用什么**。改这一个变量并重启，即可全链路换模型，**无需触碰任何 `.py`**。这也正是本项目「模型切换仅需修改环境变量」的设计约定。

### 前提（一次性准备）

1. 保持使用**通用（按量付费）Key**，并给要用的模型在控制台开启「**免费额度用完即停**」，从源头杜绝扣费；
2. 在 `.env` 里维护一份**候选池菜单**（均为"已开启 + 有额度"的通用对话模型，按到期时间近→远排序），供切换时按序取用；
3. 把 `OPENAI_MODEL` 的默认值指向池首（一个有额度模型），确保起步就走免费额度。

> 当前 `.env` 已按此配置：`OPENAI_MODEL` 为唯一切换开关，其下附有按到期日分组的候选池注释。

### 操作步骤（日常循环）

1. 到百炼控制台「**模型用量 / 免费额度**」页，查看 `OPENAI_MODEL` 当前模型的剩余额度；
2. 额度偏低时，把 `.env` 里 `OPENAI_MODEL=` 这一行的值，换成候选池中下一个仍有额度的模型名；
3. 保存 `.env`，**重启服务**（`uv run mda dev .`）使新值生效；
4. 若该模型报 `enable_thinking` 相关 400 错误，把 `DISABLE_THINKING` 改为 `false` 再重启即可回退。

### 注意事项

- **必须重启**：dotenv 在模块导入时加载、无热重载，改完 `.env` 需重启进程才生效（这是运行动作，不算改源码）。
- **额度数据非实时**：控制台为分钟级更新且需手动刷新，且无查询 API，"剩多少"只能靠人工看页面判断——本工作流正是绕开该平台限制的务实选择。
- **排序按到期时间**：优先消耗快到期的模型额度；同一天的批次内可按能力档（max→plus→flash）择用。
- **仅收录通用对话模型**：翻译/意图识别等专用模型（如 `qwen-mt-flash`）不进候选池，避免工具调用与结构化输出异常。

## 七、速查结论（一句话版）

- **Key**：账户级通行证，可调任意有权限模型；`.env` 那把是"按量付费通用 Key"，与"给哪个模型建的"无关。
- **Base URL**：只是请求地址，不触发调用、不代表计费、不体现 Key 类型。
- **扣费**：先看目标模型有没有免费额度；有则先扣额度，无则扣余额。之前被扣是因为 `qwen3.6-flash` 无额度。
- **省钱**：保持通用 Key 不变，把 `OPENAI_MODEL` 换成"有免费额度且已开用完即停"的模型（如 `qwen3.7-plus`）即可。
- **自动化**：平台无额度查询 API 与用完提醒；真正的自动切换要靠"报错驱动 + 模型池"在本地实现。
